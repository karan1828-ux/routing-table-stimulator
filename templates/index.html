Computer Networks Routing Theory Guide

A comprehensive educational companion for understanding Shortest Path Routing, Link State protocols, Distance Vector equations, and routing loop remedies.

1. Fundamentals of Network Routing

In computer networking, routing is the process of selecting paths across a network of interconnected routers to transfer data packets from a source host to a destination host.

Forwarding vs. Routing:
• Routing (Control Plane): Network-wide logic that computes end-to-end paths (routing tables) using algorithms like Dijkstra or Bellman-Ford.
• Forwarding (Data Plane): Router-local hardware/software action of transferring a packet from an input interface to an output interface based on the routing table.

A Routing Table typically maintains entries with: Destination Network / IP, Cost / Metric, Next-Hop Router, and Outbound Interface. The Next Hop is the address of the next immediate gateway router along the optimal path.

2. Link-State Routing & Dijkstra's Algorithm

In Link-State Routing (exemplified by modern internet protocols like OSPF and IS-IS), every router possesses a global and complete picture of the entire network topology.

How Link-State Works:

  1. Neighbor Discovery: Each router sends HELLO packets to identify directly connected neighbors.
  2. LSP / LSA Flooding: Each router creates a Link State Packet (LSP) advertising its connected links and costs, and reliably floods it to every other router in the Autonomous System.
  3. Link State Database (LSDB): Every router assembles these packets into an identical global topology database.
  4. Shortest Path Tree (SPT): Each router independently runs Dijkstra's Algorithm using itself as the root to construct the shortest-path forwarding tree.
Dijkstra's Shortest Path Algorithm:
Maintains a tentative cost to each node. At each step, it extracts the unvisited node with the lowest cost, marks it as permanently settled (visited), and relaxes all outgoing edges to its unvisited neighbors:
If dist[u] + cost(u, v) < dist[v], then dist[v] = dist[u] + cost(u, v) and pred[v] = u.

3. Distance-Vector Routing & Bellman-Ford

In Distance-Vector Routing (used in protocols such as RIP - Routing Information Protocol), routers do not know the global topology. Instead, they only know:

  • The direct costs to their physical neighbors.
  • The distance vectors sent to them by their physical neighbors.

This is often referred to as "routing by rumor". Each router updates its table using the Bellman-Ford Equation:

Bellman-Ford Equation:
D_x(y) = min_v [ c(x, v) + D_v(y) ]
Where router x computes its shortest distance to destination y by taking the minimum over all direct neighbors v of the link cost c(x, v) plus neighbor v's reported distance to y.

4. Comparison: Link-State vs. Distance-Vector

Feature Link-State (Dijkstra / OSPF) Distance-Vector (Bellman-Ford / RIP)
Knowledge of Topology Global: Complete view of all routers and links. Local: Only knows direct neighbors and their vectors.
Routing Protocol Examples OSPF, IS-IS RIPv1, RIPv2, IGRP, EIGRP (hybrid)
Message Exchanges Floods link state advertisements (LSAs) across entire network. Exchanges full routing vectors only with adjacent neighbors.
Convergence Speed Very Fast: Reacts swiftly to link failures. Slow: Routing updates propagate hop-by-hop.
Routing Loops Rare / Transient: Routers share consistent graph views. Susceptible to loops & Count-to-Infinity problem.
Memory & CPU Overhead Higher: Requires memory for full LSDB and CPU for Dijkstra. Lower: Modest memory and computation per router.
Negative Edge Weights Not supported (Dijkstra fails with negative cycles). Supported theoretically by Bellman-Ford (without negative cycles).

5. The Count-to-Infinity Problem & Remedies

The Count-to-Infinity Problem is a classic flaw in Distance Vector protocols that occurs when a link breaks or a destination network goes offline.

Root Cause:

When a router loses its connection to a destination, its neighbor still has a stale route pointing back through that router. Because distance vectors do not carry full path trajectories, the disconnected router erroneously believes its neighbor offers an alternate bypass path! Both routers increment their costs mutually on each round, creating a routing loop that persists until costs reach infinity.

Standard Solutions:

Split Horizon

A router never advertises a route back out the interface or to the neighbor from which that route was originally learned.

Poison Reverse

The router advertises the route back to the learning neighbor, but explicitly overwrites the metric to ∞ (16).

Hold-Down Timers

When a router is informed of a route failure, it starts a timer and refuses any new advertisements for that destination until the timer expires.
